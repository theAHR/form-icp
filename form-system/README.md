# سامانه عضویت حزب مؤتلفه اسلامی

سورس یک Modular Monolith فارسی و RTL برای فرم‌های پویا، بررسی درخواست عضویت و مدیریت اعضای حزب مؤتلفه اسلامی. داده‌ها در PostgreSQL ذخیره می‌شوند؛ قابلیت‌های اصلی به API و دیتابیس واقعی متصل‌اند.

**راهنمای کاربران (ساده، غیرفنی):** [docs/USER-GUIDE.fa.md](docs/USER-GUIDE.fa.md)

**از اینجا شروع کنید:** راه‌اندازی Docker در بخش بعد.

## دامنه این نسخه

دو فرم اولیه بر اساس کاربرگ‌های رسمی حزب از Seed ساخته می‌شوند:

- «برگ تقاضای عضویت» (نمونه ۱): مشخصات فردی، مهارت‌ها، آشنایی با حزب، هدف عضویت و مشخصات معرف.
- «کاربرگ اظهارات متقاضی در زمان مصاحبه» (نمونه ۳): مشخصات، سوابق سیاسی/اجتماعی، تمایل به بخش‌های حزب، فضای مجازی و تعهد پرداخت حق عضویت.

نقش‌ها و فرم‌های اولیه از Seed ساخته می‌شوند؛ پاسخ یا عضو نمایشی در Seed وجود ندارد.

## راه‌اندازی سریع با Docker

نیازمندی‌ها: Docker Engine + Compose v2، یا Docker Desktop با Linux Containers. برای تولید تنظیمات اولیه، Node.js 24 لازم است؛ در صورت نبود Node، `.env.example` را به `.env` کپی و مقادیر آن را دستی تکمیل کنید.

```bash
node scripts/configure.mjs
docker compose up -d --build
docker compose --profile tools run --rm seed
```

سپس `http://localhost:3000` را باز کنید. نام کاربری اولیه `admin` است. رمز اولیه به‌صورت تصادفی در `SEED_ADMIN_PASSWORD` فایل `.env` قرار دارد؛ ابزار آن را در خروجی چاپ نمی‌کند. پس از ورود، **تغییر رمز اولیه اجباری است**. بعد از Seed موفق، مقدار `SEED_ADMIN_PASSWORD` را از `.env` حذف کنید؛ Seed مجدد نباید برای بازنشانی رمز استفاده شود.

- سرویس `migrate` قبل از شروع برنامه، Migrationها را اجرا می‌کند.
- PostgreSQL از بیرون Compose پورت عمومی ندارد.
- برنامه روی پورت `3000` همهٔ کارت‌های شبکهٔ سرور در دسترس است تا کاربران شبکهٔ داخلی وصل شوند. برای محدود کردن به خود سرور، در `.env` بنویسید `APP_BIND=127.0.0.1`.
- اطلاعات دیتابیس و تصاویر در دو Volume مستقل هستند. `docker compose down -v` آن‌ها را حذف می‌کند؛ برای توقف عادی از این گزینه استفاده نکنید.
## استفاده در شبکهٔ داخلی (LAN)

سامانه روی یک کیس به‌عنوان سرور داخلی اجرا می‌شود و کاربران همان شبکه با مرورگر به آن وصل می‌شوند؛ اینترنت لازم نیست.

1. به کیس سرور یک **IP ثابت** بدهید (در تنظیمات کارت شبکهٔ ویندوز یا رزرو IP در مودم/روتر)، مثلاً `192.168.1.10`.
2. در `.env` سرور، `APP_URL` را با همین IP بنویسید: `APP_URL=http://192.168.1.10:3000`. `COOKIE_SECURE=false` بماند، چون اتصال HTTP است.
3. پورت ۳۰۰۰ را در فایروال ویندوز سرور باز کنید (PowerShell با دسترسی Administrator):

   ```powershell
   New-NetFirewallRule -DisplayName "Membership 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private,Domain
   ```

   پروفایل شبکهٔ سرور باید «Private» باشد، نه «Public».
4. کاربران در مرورگر نشانی `http://192.168.1.10:3000` را باز می‌کنند.

## اجرای توسعه

Node.js 24 و PostgreSQL 17 را نصب کنید. یک دیتابیس خالی بسازید و `DATABASE_URL` را تنظیم کنید.

```bash
npm ci
node scripts/configure.mjs
npm run db:migrate
npm run db:seed
npm run dev
```

اگر `.env` را قبلاً ساخته‌اید، فرمان configure را دوباره اجرا نکنید. در اجرای محلی، حساب و رمز DATABASE_URL باید با PostgreSQL شما یکسان باشد. Compose عمداً دیتابیس را به میزبان منتشر نمی‌کند؛ توسعه محلی نیازمند PostgreSQL محلی یا تنظیم آگاهانه پورت است.

برای Build و اجرای تولیدی خارج Docker:

```bash
npm run build
npm start
```

`npm start` خروجی standalone را با تنظیمات `.env` و فایل‌های static آماده‌شده اجرا می‌کند. پیش‌فرض میزبان `127.0.0.1` است؛ `APP_HOST` و `PORT` قابل تنظیم‌اند. `APP_URL` باید دقیقاً نشانی مورد استفاده مرورگر باشد؛ کنترل مبدأ POST بر اساس آن انجام می‌شود. اگر پورت ۳۰۰۰ اشغال است، با `npm run dev -- -p 3005` پورت دیگری انتخاب کنید و **`APP_URL` را دقیقاً با همان پورت هماهنگ کنید**.

### حساب‌های صرفاً توسعه

با تنظیم `ALLOW_DEV_SEED=true` و خارج از `NODE_ENV=production`، Seed چهار حساب `admin`، `manager`، `operator` و `viewer` را می‌سازد. رمز هر چهار حساب یکی است: اگر `SEED_ADMIN_PASSWORD` خالی باشد رمز **`Admin@123456`** است، وگرنه همان مقدار `SEED_ADMIN_PASSWORD` استفاده می‌شود (باید ۱۲ تا ۷۲ نویسه و شامل حرف انگلیسی و عدد باشد). این رمز **فقط توسعه** است؛ در محیط واقعی مجاز نیست و همه حساب‌ها در اولین ورود باید آن را تغییر دهند. Seed تولیدی فقط مدیر ارشد اولیه و تعریف نقش‌ها را ایجاد می‌کند؛ کاربران دیگر را از پنل بسازید.

## مسیر استفاده

1. ورود و تغییر رمز اولیه.
2. «کاربران» (مدیر): ساخت حساب اپراتور و انتخاب نقش.
3. «فرم‌ساز» (**فقط مدیر**): طراحی یا ویرایش فرم و انتشار.
4. «ثبت فرم» (**اپراتور / مدیر**): تکمیل «برگ تقاضای عضویت» و ثبت درخواست جدید.
5. «درخواست‌ها»: بررسی درخواست؛ از همین‌جا فرم مصاحبه یا تکمیلی را تکمیل کنید.
6. در صورت نیاز، ثبت پاسخ اصلاحی جدید؛ پاسخ قبلی حذف یا بازنویسی نمی‌شود.
7. تأیید درخواست به‌صورت تراکنشی یک عضو و شماره عضویت ایجاد می‌کند؛ رد یا درخواست اصلاح نیازمند دلیل است.
8. «اعضا»: تنظیم نوع، وضعیت، تاریخ انقضا و عکس عضو.
9. دریافت CSV، مشاهده Audit و تهیه پشتیبان.

متقاضی عمومی می‌تواند بدون ورود، فرم عمومی را در `/forms/membership-application` پر کند.

## تست و حدود تأیید

```bash
npm test
npm run typecheck
npm run build
```

آزمایش یکپارچه **فقط روی دیتابیس آزمایشی تازه**، با چهار حساب توسعه و برنامه در حال اجرا:

```bash
# Bash; در PowerShell: $env:ALLOW_INTEGRATION_TESTS="yes"
ALLOW_INTEGRATION_TESTS=yes npm run test:integration
npx playwright install chromium
npm run test:e2e
```

آزمایش یکپارچه حساب‌ها و داده‌ها را تغییر می‌دهد، رمزهای توسعه را عوض می‌کند و viewer را غیرفعال می‌کند. هر بار از DB خالی Seedشده استفاده کنید. `E2E_PASSWORD` رمز مدیر برای تست مرورگر است؛ پیش‌فرض با رمز آزمایشی integration برابر است.

[گزارش آزمون تحویل](docs/VALIDATION.md) دقیقاً آزمون‌های اجراشده و آزمون‌های باقی‌مانده را مشخص می‌کند. این پروژه دارای Build تولیدی و کنترل‌های امنیتی است، اما گواهی امنیت یا ادعای تأیید استقرار روی شبکه شما ندارد. پیش از ورود داده واقعی، آزمون پذیرش روی PostgreSQL و Windows هدف، TLS، Restore و سیاست نگهداری داده را انجام دهید.

## محدودیت‌های روشن

- گروه تکرارشونده یک سطح دارد، حداکثر ۳۰ ردیف؛ شرط‌ها equality و ارجاع به فیلد قبلی همان گروه هستند. معماری برای توسعه این قواعد آماده است.
- File/Image فعلاً فقط JPEG/PNG/WebP تا ۵ MiB می‌پذیرند؛ PDF، Office و امضای دیجیتال/دستخط پیاده‌سازی نشده‌اند. وضعیت امضای کاغذی ذخیره می‌شود.
- ورودی تاریخ HTML میلادی است؛ نمایش تاریخ‌ها فارسی است. تقویم جلالی انتخاب‌گر در این نسخه وجود ندارد.
- Export فعلاً CSV و حداکثر ۱۰٬۰۰۰ رکورد است؛ Excel می‌تواند فایل را باز کند. گزارش PDF/XLSX در دامنه این نسخه نیست.
- مسئول درخواست با شناسه کاربر تعیین می‌شود؛ محدودیت مالکیت درخواست مستقل از نقش در این نسخه فعال نیست. اپراتورها درخواست‌های غیرمحدود را می‌بینند.
- SSO/MFA، اسکن ضدبدافزار خارجی، رمزنگاری فیلدی/KMS، امضای زنجیره Audit و اجرای خودکار سیاست حذف داده وجود ندارند. ذخیره‌سازی فعلاً Local است؛ NAS با Volume و S3/MinIO با Adapter قابل افزودن است.
- تغییر نگاشت فرم، مشخصات Person موجود را خودکار بازنویسی نمی‌کند؛ تطبیق اصلاحات هویتی به روال مستقل و بازبینی‌شده نیاز دارد.
