# امنیت، نقش‌ها و نگهداری داده

مجوزها در سرور و سرویس دامنه بررسی می‌شوند. پنهان‌سازی منو کنترل امنیتی اصلی نیست. صفحات مدیریت قبل از Render نیز نشست را بررسی می‌کنند. هیچ routeای passwordHash را به مرورگر ارسال نمی‌کند. مدیر نمی‌تواند خودش را غیرفعال یا نقش خودش را عوض کند؛ آخرین مدیر ارشد حفظ می‌شود.

## کنترل‌های پیاده‌شده

- bcrypt cost 12؛ ۱۲ تا ۷۲ نویسه، شامل حروف انگلیسی و عدد، حداکثر ۷۲ بایت برای محدودیت bcrypt.
- Session تصادفی ۲۵۶بیتی؛ فقط HMAC آن در DB، انقضای ثابت ۸ ساعت، HttpOnly و SameSite=Strict. Secure با `COOKIE_SECURE=true` در TLS.
- بررسی دقیق Origin برای همه POSTها از جمله Login. فایل یا نشست ارسال‌شده با مبدأ دیگر رد می‌شود.
- محدودسازی مشترک بین فرآیندها در PostgreSQL: ورود ۱۰ تلاش/نام کاربری/۱۵ دقیقه، ۱۰۰ تلاش/IP؛ ثبت عمومی ۲۰/ساعت، فایل ۳۰/ساعت و استعلام ۱۰۰/دقیقه.
- اگر TRUST_PROXY=false باشد، IP با مقدار direct ثبت و نرخ‌های عمومی مشترک می‌شوند. برای شبکه واقعی با Proxy قابل اعتماد تنظیم شود؛ هرگز X-Forwarded-For اینترنتی را بدون پاک‌سازی نپذیرید.
- schema strict، محدودیت اندازه و تعداد، عدم پذیرش HTML از فرم‌ساز، escape متن کارت، پارامترهای Prisma و raw SQL فقط tagged template.
- فایل فقط تصویر raster قابل decode، سقف pixel، بازکدگذاری به JPEG و حذف metadata؛ فایل خارج web root و مسیر تصادفی با mode محدود.
- پیوست ثبت‌نشده فقط توسط مالک قابل اتصال است؛ پس از اتصال، سطح دسترسی Submission و حساسیت snapshot کنترل می‌شود.
- حساسیت نسخه قدیمی با انتشار نسخه جدید عمومی‌تر تغییر نمی‌کند. پاسخ و schema نسخه‌ها از طریق trigger غیرقابل تغییر هستند.
- Audit فاقد جواب فرم، رمز و secret است. تراکنش تغییر حساس بدون Audit موفق commit نمی‌شود. مشاهده پاسخ محدود و Export ثبت می‌شوند.
- CSP، nosniff، DENY framing و same-origin referrer. CSP برای Bootstrap Next.js فعلاً unsafe-inline دارد؛ nonce-based CSP در این نسخه پیاده‌سازی نشده است.

## کنترل‌های استقرار

TLS و disk/volume encryption باید در زیرساخت انجام شوند؛ برنامه ادعای encryption at rest در سطح فیلد ندارد. فایل `.env` را با دسترسی محدود و خارج Git نگه دارید. Secret نشست و چاپ باید مستقل باشند. برنامه و agent را با حساب سرویس محدود اجرا کنید. DB runtime در استقرار سخت‌گیرانه باید از کاربر مالک Migration جدا شود؛ نمونه Compose برای شروع از یک حساب DB استفاده می‌کند. Triggerهای append-only در برابر مالک دیتابیس یا مدیر زیرساخت tamper-proof نیستند.

اجرای شبکه‌ای Agent فقط پشت firewall و TLS/mTLS یا تونل امن؛ Bearer token را روی شبکه غیرقابل اعتماد HTTP نفرستید. صفحه verify به‌شکل عمدی مشخصات فرد را نمایش نمی‌دهد. داشتن QR تنها اعتبار کارت را نشان می‌دهد و ابزار اثبات هویت نیست.

## نگهداری و حذف

مدت نگهداری، مبنای رضایت، پاسخ به اصلاح/حذف، دسترسی backup و audit باید توسط سازمان تعیین شود. حذف خودکار هویت/تاریخچه عمداً در UI تعبیه نشده است؛ برای اجرای سیاست مصوب، migration/رویه مدیریتی بازبینی‌شده بنویسید. Trigger تغییرناپذیری تاریخچه را بدون بررسی دور نزنید.

Fileهای بارگذاری‌شده ولی متصل‌نشده و Session/RateLimitهای منقضی نیازمند برنامه پاک‌سازی هستند. اسکریپت `scripts/cleanup.ts` فقط نشست و rate-limit منقضی را حذف می‌کند؛ فایل یتیم خودکار حذف نمی‌شود تا عکس عضو/لوگوی قالب از دست نرود. حجم دیسک را پایش کنید.

به‌روزرسانی وابستگی‌ها، تست نفوذ و ارزیابی زیرساخت بخشی از تحویل اجرایی سازمان است. بسته یک تأییدیه امنیتی مستقل محسوب نمی‌شود.

## وابستگی‌های اصلاح‌شده در تحویل

در اسکن ۲۰۲۶-۰۹-۲۳، Sharp به 0.35.4 ارتقا یافت. برای بسته‌های ابزار Prisma، `effect` روی 3.22.2 و `deepmerge-ts` روی 8.0.2 با npm overrides قفل شدند. هدف، رفع advisoryهای شناخته‌شده پردازش تصویر و وابستگی‌های پیکربندی بود. پس از تغییر، generate، migration، build و آزمون‌ها تکرار شدند. این overrideها هنگام ارتقای Prisma باید دوباره بررسی شوند؛ حذف بدون اسکن و آزمون مجاز نیست.

نتیجه `npm audit --omit=dev` در زمان تحویل: صفر هشدار شناخته‌شده. این نتیجه زمان‌مند است و به معنی نبود آسیب‌پذیری ناشناخته یا تأیید امنیت طراحی نیست.
